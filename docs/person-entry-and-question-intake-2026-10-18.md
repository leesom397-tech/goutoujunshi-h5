# 人物入口与问成子使用逻辑

本轮基线为 `822129b`，沿用当前仓库的抽象动效、完整资料背书和已有全量分析能力。此文件记录本轮实际修改，不替代 `relationship-system-audit-2026-10-18.md` 中的能力边界。

## 入口分工

| 用户要做什么 | 浅层入口 | 使用的资料与结果 |
| --- | --- | --- |
| 看这个人的整体情况 | 首页主按钮、全站“分析一个人”、人物页、问成子顶部 | `/relationship` 先选已导入的人或导入新好友；打开准确聊天库，自动核对同人已同步朋友圈；确认费用后生成完整报告。 |
| 快速看好感线索 | 首页“好感探测器” | `/analyze?mode=chat&focus=affinity`；复用聊天上传和报告，无第二次上传或重复分析。 |
| 看某句话的意思、怎么回 | 聊天分析；截图报告三个阅读选项 | 好感探测器、逐句意图、怎么回。切换只读报告。完整历史报告仍为看清现状、看见变化、决定下一步，不恢复40条样本逐句。 |
| 直接提问 | 问成子 | 可先选人物；有已授权档案/聊天则先使用，没有实际背景才问关系与认识时间、最近具体事件；可跳过，背景补充本身不调用模型或扣费。 |

好感分数是已有模型结果对可见互动的概括，不宣称喜欢概率。0 是有效结果，未知项不补成0；没有总分时显示待判断。此次没有新增评分公式。

## 本轮补齐

- 已导入人物入口每页6项、有搜索与已有报告入口，避免材料列表无限延伸；已保存报告与重新分析分开。
- 跨设备配对同人朋友圈不依赖旧浏览器 localStorage。必须同账号、同微信账号、同联系人标识；旧记录必须有明确共享人物关联，不能仅凭同名合并。
- 打开资料不会自动分析；朋友圈读取未完成或失败时明确状态并防止静默遗漏。
- 报告读取接口比对原快照的版本与实际记录数。新增、修正、删除、重新关联分别显示状态；只读访问不重新收费。
- 问成子显式显示当前人物，回答可展开查看资料数及语义报告是否完成，保留全量统计与按问题检索的区别。
- 没有背景时网页只问两个短问题。旧小程序尚未实现该表单，接口通过 `supportsClarification` 保持兼容。
- 背景在截图提问、补全回答及原话校验中都保留；换人物/新对话/换方式不串用背景。
- 已收费请求优先恢复原收据，再考虑当前档案状态；补充背景不生成收费任务。测试包括档案变化后重试、不同正文复用请求号被拒绝。
- 导入90秒没有新进度显示真实停滞时间与操作；分析显示用时，不承诺离开后一定自动完成。

## 验证

合成人物与本地 SQLite、浏览器拦截服务；未读取真实聊天或调用付费模型。

- `node scripts/test-person-entry.mjs`：身份隔离、旧库关联、来源版本变化/删除/改人、未知状态。
- `node scripts/test-person-entry-browser.mjs`：1440/390视口，人物入口到准确库、同人朋友圈、费用确认、三选项、补背景、保留原问题、无溢出；切换不调用分析。
- `node scripts/test-person-import-browser.mjs`：联合导入成功、朋友圈失败、账号不符、旧助手。
- `node scripts/test-report-reading-depth-browser.mjs`：完整报告原有三任务、无逐句样本、原话依据、展开返回位置。
- `node scripts/test-quick-question.mjs`：17组，免费追问、本人档案不能代替对方背景、已知背景复用、图片/修复/引文、收费收据恢复。
- `node scripts/test-evidence-context.mjs`：10组，授权资料和事件引用、真实SQLite、一次调用与收费。
- `npx tsc --noEmit --incremental false`：类型检查。

## 仍有明确边界

- 新鲜度检查只核对报告原来纳入的资料库；后续另建的其他资料库和用户资料修正，不在本轮自动发现范围。
- 完整语义报告尚不是持久后台任务；大量文字/图片长请求的断线续算仍需后续实现。本轮只补真实状态，不能据此认定长任务问题完全解决。
- Windows 助手依旧需要可信代码签名证书才能改变签名状态；本轮没有签名或重打包助手。
- 朋友圈只能采集微信可见范围，图像分析以成功同步的预览为准。不能承诺取得全部历史或所有原图。
- 千问实际生成的措辞和关系判断质量仍需授权案例验收；合成输出的测试仅证明数据链路与交互。
