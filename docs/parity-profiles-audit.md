# 人物档案与新建人物：小程序 / 网页逐项审计

审计日期：2026-10-09。范围为实际运行页面 `miniapp/pages/archive`、`miniapp/pages/person-new`，共享朋友圈模板，以及网页 `app/archive`、`app/person-new` 和 `components/Archive*.tsx`。以 WXML 中真正渲染的条件和绑定事件为基准；没有把未接入的库函数当成产品功能。

## 本轮发现与修复

1. **基础资料线索回填**：网页此前仅展示人物对象的字段。现在和小程序一样，在手填字段为空时，取本人物最新的 accepted/pending 基础线索；pending 明示“待确认”，不会写成已确认资料。手填值优先，其他人物的线索不能串入。
2. **缺失维度雷达图**：网页此前按返回行数生成轴，老档案缺项时可能缩成非六维图。现固定六轴，仅合法 0–100 数值绘点；0 是有效观察，缺失/NaN/越界值为未知，六项未齐时不画面积多边形。
3. **长期趋势展示**：图表对齐小程序最近八个有日期节点，保留未知分数的日期位置；未知、不可比较或前序报告不匹配时断线。完整历史仍显示在时间线中。
4. **朋友圈统计分母**：补齐去重总量、可分类量、未分类量、可分类文案量、自拍比例与无法判断数量。完全没有可判断自拍时不显示空白百分比。
5. **反馈修订**：历史补齐每次 `review`，区分首次反馈和更新反馈；增加“还没行动 / 有进展 / 还在等回应 / 让我不舒服”四个快捷保存入口，保留详细六结果表单、备注与日期草稿。
6. **小程序同版视觉**：档案与新建人物使用明亮冰蓝玻璃、同一关系配图、柔和边框、深色正文和轻入场效果；减少动态效果偏好关闭动画。雷达公共绘制库仅更新颜色，未改原计算逻辑。
7. **小程序新建字段**：把现有 `input` 处理器已经支持的 `lifestyle`、`values`、`boundaries` 显示为可选项，与网页一致。未修改两个页面的 JS 事件逻辑。

## 真实限制与待确认事项

- 本轮新增代码的原生微信视觉效果需要根代理的模拟器/真机检查。源码与模拟事件测试通过不等于已经证明所有设备像素一致。
- 网页和小程序共用分析、资料、趋势、反馈规则，但网页账号与微信账号的认证入口不同；跨端账号关联属于账户模块审计范围。
- 反馈草稿目前是当前页面内保存，刷新页面不会自动恢复未提交草稿；这与原小程序内存草稿机制一致。
- 本页没有聊天原始数据导出、专用预约管理，也没有自动判断真实爱意或心理诊断。这些不应包装成已有功能。
- 样式包含原生 Canvas、Web SVG、微信 picker 与浏览器 select 等平台实现差异；保留相同数据含义、操作结果和未知值规则。
- 此审计没有部署；最终构建和生产发布由根代理统一完成。
