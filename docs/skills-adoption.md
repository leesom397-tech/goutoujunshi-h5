## 2. wechat-chat-analysis：采用、去重和排除

新增：knowledge/references/practical/人物核对与多对象比较：证据、需求和约会复盘.md。

产品旧版本已经在第三方说明中提过此仓库，也有八维相关观察、原话优先、数字边界和约会反思题。因此没有再称“新增八维分析”，也没有复制八维 1–5 分评分卡。

| 上游启发 | 本次补足的操作要求 |
| --- | --- |
| 前后矛盾、交叉验证 | 双记录核对表：同一人的两条原话，各有来源和时间；先排除生活变化、时间范围不同、口误、转述、错序和身份混淆；缺项只标待核对 |
| 年龄/地点/职业/收入/资产/婚恋/账号差异 | 提供这些字段的可比性检查，不把出差当搬家、不把税前税后混比、不因同款照片判定同一账号持有人 |
| 先说明自己再提问 | 只使用用户真实表达的需要，再给一个中性问题并允许不回答；不编造经历，不保证答案一定真实 |
| 多对象横向比较 | 先按用户的明确需要逐人填已知、来源时间、未知和可能影响；资料少不等于差，不补零、不强排、不做人格分；比较的是待核对信息和行动代价 |
| dating 复盘 | 用事实/用户感受/待验证/一个下一步四格，不把感受写成对方事实，不为传播制造“破案”故事 |

未采用：经济外观验真、职业/性别刻板印象、固定人设类型、三处矛盾即包装、统一两周观察、灌酒套话/跟踪住址/查设备、把对象当对照组、固定人生阶段期限、导出与密钥脚本。

其中“确认前后矛盾需两条原话”只限定一致性判断。一条威胁、暴力或明确拒绝已经足够触发相应边界，不能等待第二条才回应。

## 真实接入路径

1. 两份 Markdown 经 scripts/build-knowledge.mjs 生成 lib/knowledge.generated.json。
2. 同时生成 lib/knowledge-manifest.generated.json 与 miniapp/lib/knowledge-stats.js；公开方法标签可追到来源页。
3. lib/knowledge.ts 增加具体意图路由，位于泛化的聊天/回复路由之前；安全路由仍第一。已有默认参考和 1–3 份上限保留。
4. buildKnowledgeContext 的产品自称由遗留 LoveTalk 改成成子；参考来源在第三方说明中如实保留。
5. lib/crush/quick.ts 的 quickJudgment 根据真实可读正文选参考；相关主题会注入新指南前 1000 字。
6. app/api/miniapp/text/route.ts 的 chat / conversation / positioning 共用选择逻辑，注入前 850 字；app/api/web/text/route.ts 直接重导出同一 POST。
7. lib/crush/advice.ts、聊天、语音摘要等已有 buildKnowledgeContext 消费者无需重复粘贴提示，命中主题时自动获得新指南。截图后续回复等 selectKnowledge 消费者按实际查询命中。

两份指南的必要证据与安全边界均放在前 850 字，短提示也不会只得到技巧而漏掉限制。没有将参考指令当个人事实，也没有引入新后台表或付费调用。

## 实际限制

- 这是方法检索与提示增强，不是一个独立、确定性的矛盾检测器；没有声称能证明某人撒谎、诊断人格或判断真实爱意。
- 未用付费模型进行回答质量评测；测试证明真实调用路径携带正确方法与约束，不保证每次模型输出都完全遵循，需要已有证据核对与用户修正。
- 参考按输入文字/明确问题触发。尚无可读正文的 OCR 前置调用不一定命中新主题；不能声称所有图片都会完整套用两份指南。
- 多对象只读对照 UI 由根代理另行协调；本接入不自动把各对象原始聊天混入一个模型请求，不改账号归属或资料授权范围。
- 保留方法出处不等于把上游所有主张作为研究结论。未新增上游硬编码的成功率或诊断准确率。
