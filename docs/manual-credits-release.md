# 手动权限与积分：发布门禁（2026-10-06）

用户最新确认：不要赠送 100 积分。新账号默认 0，旧账号进入也不自动补赠。
不依据审核身份、渠道、版本或时间切换为免权限模式；不提供购买、转账引导。

## 本地已实现

- `0015_account_credits.sql`：零余额账号、人工分配流水、功能权限操作记录、任务冻结/结算/退回。
- 数据库约束与触发器保证余额不为负、操作幂等及失败仅退回一次。
- `/api/miniapp/credits`：只读取当前登录账号，首次创建时严格为零。
- `/api/miniapp/admin/credits`：按公开用户编号查找、调整积分、设置功能与有效期。
- 管理员仅由服务器 `COACH_ADMIN_OWNER_IDS` 明确指定；没有默认管理员、首登管理员或前端密钥。
- 小程序账号页：用户编号、余额、冻结数、明细；管理员才可看到管理区域。
- 新 API 明确返回 `meteringReady:false`；页面说明分析扣分尚未启用，不冒充已上线计费。

## 禁止直接提审 / 部署本候选包

当前只是账户与账本基础，不是完整商业化发布。以下项目未完成：

1. 用户提供的账号线索已在生产只读核对为唯一匹配（1 个已验证绑定、1 个独立 owner，rows_written=0）。尚未写入服务器管理员配置；部署时重新核对唯一性后再绑定。不得把手机号尾号当登录凭据或永久授权规则，文档不保存具体手机号线索。
2. 截图后台任务、旧单图入口、社交资料、文本、改写、转写、实时语音及网页同账号入口：逐项接入权限与积分，消除可绕过的付费功能入口。
3. 异步任务创建前冻结，最终结果持久化后结算；可重试错误不能提前退款，取消/终止需退回；结果与积分状态需可恢复对账。不能依赖前台轮询结算。
4. 在发起分析前展示并确认本次积分；余额不足、未开通、已到期时明确提示，不影响已有报告和手工档案编辑。
5. 确认扣分表，实测语音成本与时长限制；用户仅否定赠送 100 积分，不据此认定此前所有建议价格已获确认。
6. 增补隐私说明中的账号权限、积分流水和操作记录用途、保留期限与注销流程。不把关系原文写入账本。
7. 把新账本纳入数据库 schema 管理，预演迁移和前后端发布顺序，核对权限关闭后既有用户影响。
8. 补齐界面真机与端到端测试：0 积分、手动开通、失败退回、重连去重、并发、管理员越权、到期及旧版客户端。
9. 发布门禁检查、用户授权后才能迁移生产数据库、部署和上传；如实填写需开通的使用条件，为审核提供可操作的真实测试路径，不伪装成所有功能免费。
