# 好感探测器入口与能力核对

## 当前正式入口

`/analyze?mode=chat&focus=affinity` 复用截图上传、身份确认、费用确认与同一份报告。好感、逐句意图、怎么回是同一结果的三个阅读选项，切换不重新上传或分析。

| 用户操作 | 已有实现 |
| --- | --- |
| 看好感信号 | `AffinityOverview` 展示已有总分、可判断维度、实际读取范围及缺失项。分数是互动参考，不是喜欢概率。 |
| 看某句话是什么意思 | `ToneEvidence` 可逐句选择，显示情绪与意图解释权重、上下文说明、上一句/下一句，并记住阅读位置。 |
| 看怎么回 | `Replies` 展示首选/备选、原因与代价，可复制；满足本人用语样本条件后，可按标明费用改写语气。 |
| 继续补充截图 | 保留分析重点与人物上下文，已有材料去重；分析前显示费用。 |
| 看完整关系 | `/relationship` 汇总人物资料，使用完整关系报告。没有把完整历史换成40条逐句样本。 |

## 与参考来源的关系

- `vendor/crush-monitor/UPSTREAM.md` 固定记录上游 commit。情绪/意图标签表沿用，六维规则与加权、边界处理作了适配。当前截图处理 `lib/crush/screenshot.ts` 确实调用这套六维规则，结果经 `decision.affinityPreview` 进入当前报告；不是只借用了“好感探测器”的标题。
- `she-love-me` 与 `wechat-chat-analysis` 的接入记录在 `docs/skills-adoption.md`。采用互动修复、证据核对、其他解释、行动及复盘方法，没有复制上游全部报告字段、指数或界面按钮。
- 不声称与参考产品的每个按钮一致，也不把方法指南当成已经实现的独立功能。

## 为什么不把首页链接改到 `/crush`

`/crush` 是旧独立流程，保留文字粘贴、单张截图、可选第三方分布、按需六维图、分析图片导出及7天记录。它使用另一套设置/授权/历史路径，不能仅切换首页链接来替代当前统一费用确认和报告流程。

上述旧页特有操作没有在本次强行移入新页；如后续需要导出图或快速文字输入，应接入当前统一任务、计费及身份链路。

## 本次修正

- 有结果的互动维度直接展示，移除必须展开才能看到图的门槛。未知项显示“待判断”，真实0分保持0，不造数据。
- 好感卡显示“某人对你的互动信号”，主文字16px，手机320px宽度可读。
- 从好感入口打开截图报告时，先展示好感卡。存在优先风险/边界时继续先显示风险判断；完整历史报告顺序不变。
- 入口一句说明同次分析包含好感信号、逐句意图、怎么回。
- 已保存截图报告的“补充材料”链接保留 `focus`。

## 验证

`scripts/test-affinity-reader-browser.mjs` 使用真实浏览器及合成人物，在1440/390/320视口验证：六维可见、主体、0分/未知/未读媒体、逐句点击、三条回复、复制、补充入口和无横向溢出；所有API拦截，无付费请求、无真实个人资料。

`scripts/test-screenshot-entry-browser.mjs` 验证上传、左右身份、显示费用、确认后仅建立一个任务及朋友圈来源隔离。后端全部为合成返回，未调用模型。

测试证明交互与数据展示链路，不代替真实模型内容质量验收。
