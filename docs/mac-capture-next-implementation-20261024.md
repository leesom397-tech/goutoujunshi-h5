# Mac 完整采集：下一段实施与验收

2026-10-24。用户的 Mac 已能通过 UU 看到桌面，程序化终端正在接通。以下不把远控连接、应用启动或合成测试算成真实采集验收。

## 已确认的问题与本轮修复

`macos_database_source.ContactSourceCache.run()` 原来把真实 source 交给 `search_contacts_from_source()`。后者在 `finally` 中关闭 source，清空 Mac 账号证明；cache 随后再调用 `assert_unchanged()`，正常联系人查询也会校验已关闭的授权。

本轮用短期借用对象统一 source 生命周期，由 query owner 做最后一次账号校验并关闭。搜索有独立非阻塞操作锁；`clear()` 立即递增 generation，旧请求不能在清除连接后返回结果。异常清理也释放锁，不让后续搜索永久 busy。没有保存新密钥、复用陈旧数据库、修改版本允许表或放宽身份校验。

## 现状与缺口

| 路径 | 已有代码 | 下一段必须补齐 |
| --- | --- | --- |
| 微信账号授权 | 官方签名、唯一登录账号、固定上游、显式初始化、内存授权及 worker TTL | 先核对实机版本；270135 在上游仍未支持，不可只添加白名单 |
| 联系人与聊天 | 只读加密 VFS、精确联系人、分页、账号变化保护 | 修复后的真实联系人搜索、连续历史及重连测试 |
| 语音 | 原音频定位、SILK、本机 ASR 与内容寻址缓存 | 实机音频可用性、缓存命中和实际耗时 |
| 朋友圈文本 | 指定作者的 SNS 缓存 XML，分享卡片文本，稳定帖子 ID | 自动浏览产生的资料范围、增量和真实终止条件 |
| 朋友圈图片 | 当前只保留媒体数量；明确标记未读画面 | 进入详情读取指定帖子的真实图片，不能用缓存目录近似配对 |
| Mac UI | `macos_accessibility.py` 仅有无内容的 AX 诊断 | 精确导航、滚动、详情与返回状态机；当前没有这些实现 |

固定上游 main 仍为 `2225294fd0761e10ce15540f21e7dbb2ac304c3c`。[270135 / 270115 兼容问题 #26](https://github.com/labazhou2024/chatlog-keeper/issues/26) 尚未提供可直接采用的适配结果。[WeChat-MCP](https://github.com/BiboyQG/WeChat-MCP) 与 [wechat-controller](https://github.com/dragonking-T/wechat-controller) 可参考 MIT 导航、AX 与窗口截图实现，但没有证明完整相册图片、原音频链路已覆盖当前版本。

## 连接后先执行的最小检查

仅输出版本、状态与计数，不输出联系人列表、正文、账号目录或授权材料：

1. `sw_vers`、`uname -m`；读取微信 `Info.plist` 的短版本和构建号。
2. 只核验官方签名与当前运行进程归属。Mac 健康检查不能主动开始授权、关闭微信或修改系统权限。
3. 确认实际登录到 GUI 会话；读取 AX/录屏授权状态和有界无文本 AX 角色树。
4. 在用户指定联系人的相册页面校准真实窗口结构；其他联系人不做探索性扫描。
5. 若实际版本为 270135，记录 key provider 的明确阻塞。对版本差异的开发验证与普通用户授权流程分开，原版微信不改写，SIP/TCC 保持正常。

## 朋友圈最小实现边界

新增平台相册 driver，返回语义状态，不把像素坐标散落在采集循环中。接口先以实际 AX /窗口数据确定：

- `resolve_current_view()`：从当前微信应用重新查找唯一可见窗口，返回列表、详情、图片、加载中、不可读等状态。
- `verify_selected_person()`：核对用户选定的人，不能只靠容易重复的昵称。身份验证失败立即停止本轮归属。
- `read_visible_posts()`：读取当前选中相册的动态，保留真实时间、正文与可核对来源；缓存有确切帖子 ID 时用其稳定 ID。
- `open_post()` / `read_post_images()`：先进入并核对该帖详情，再读取确实可见的图片；图片对应哪条动态必须由详情上下文证明。
- `return_to_album()`：返回后丢弃旧 AX 引用，重新解析可见列表。普通相册与置顶列表分别验证。
- `advance_album()`：一次滚动后等待内容指纹变化或明确末尾提示；重试有上限，使用短间隔状态检查，不使用固定数秒休眠。

### 有界状态机

`核对人物 → 列表读取 → 逐帖详情 → 逐图读取 → 返回并重绑定 → 下一屏 → 确认末尾`。

每个阶段都检查取消、账号/人物归属和时间预算。详情失败只标记该帖媒体未读，保留已验证文本；错误弹窗、权限丢失、相册关闭或窗口遮挡不允许被误判成已到末尾。只在明确的可见末尾或产品规定范围内返回对应完成状态。

聊天与语音在已授权的只读后台链路中运行，朋友圈 driver 独占前台 UI。后台转写不应抢微信焦点；取消一个阶段不应删除另一个阶段已完成的记录。

### 图片正确性

- 从已核对的详情取得实际图片，保留张数、原始长宽与清晰度；不把封面、头像或屏幕占位当成动态图片。
- 一条动态的不同图片以图片索引/来源和内容摘要去重；仅因为同样尺寸、相近时间或相似文件名不能配对。
- 仅本机处理界面定位所需文字和图片，不为了寻找按钮把全屏聊天传给外部视觉服务。
- AX 缺失时需要在已确认的微信窗口内使用本机 OCR/视觉定位，并再次验证目标状态；不可用全屏绝对坐标盲点。
- 当前缓存解析继续返回 `complete=false`；不要把“缓存扫描结束”改名成“全部可见朋友圈完成”。

## 必须覆盖的回归和真机验收

合成 driver 用不含真实用户数据的状态序列测试：进入/返回重建 AX 对象、隐藏旧列表、置顶切换、加载延迟、页面未移动、详情读取失败、重复图片、取消、账号变化以及假末尾。

真实单联系人验收至少包括：

1. 一次搜索显示正确人物与头像，重复搜索没有排队卡顿。
2. 连续聊天分页无重复/缺页，语音命中缓存不再次转写。
3. 普通和置顶动态都可读；人工核对少量动态的正文、时间、每帖图片张数及图片归属。
4. 采集途中返回/重开详情、短时网络慢、手动取消与继续，已保存内容不丢且不重复。
5. 相册明确到末尾才标记全量；遇到限权、未读图片或预算结束要保留准确缺口。
6. 非敏感验收结果只记录版本、计数、时长、阶段和错误码，不上传真实聊天全文或授权材料到 CI。

**验收顺序：联系人搜索 → 聊天 → 缓存语音 → 当前相册一屏 → 单帖所有图片 → 跨屏与置顶 → 端到端。** 每一步通过后再扩展，避免一次请求包裹所有未验证能力而让用户再次等待数分钟才失败。
