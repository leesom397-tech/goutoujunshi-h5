# 手机录屏导入

入口：`/capture?method=video&kind=chat` 或 `kind=moments`。聊天与朋友圈上传区都提供「导入手机录屏」。手机直接打开 `/capture` 时默认选择录屏方式。

## 使用流程

1. 在微信中打开一位好友的聊天或朋友圈，录屏并缓慢滑动，每屏停留 1–2 秒。
2. 在网页选择视频，选定开始、结束时间；可框选正文区域，避开状态栏等无关内容。
3. 提取画面后放大核对，删除不需要的截图，调整顺序。向上翻聊天的录屏通常需要倒序为「最早 → 最新」。
4. 确认截图后，网页在本机保存所选画面，直接进入现有截图分析页。核对左右身份及处理范围，再确认分析。

## 范围与边界

- 原视频通过浏览器本地 `blob:` URL 解码，不上传视频，也不读取音轨。
- 视频最大 200 MiB、5 分钟；每次选段最多 90 秒、180 次采样、9 张画面；所保留图片总计不超过 20 MB。
- 达到数量或大小上限会显示实际停止位置，后续需要分段处理。不会把未处理的后半段说成已经完成。
- 自动跳过重复、正在滑动和黑屏画面；同一录屏的重叠片段会再次核对已有画面，避免压缩噪声导致重复保存。用户仍需核对是否漏页、文字是否清晰；画面去重不等于消息去重。
- 保留每张截图的录屏位置，不能当作消息时间。顺序以用户确认后的数组为准，来源随截图删除与调序保持一致。
- MP4/H.264 为兼容性优先格式。MOV、HEVC、WebM 是否可读由设备和浏览器解码能力决定；解码失败可在相册另存兼容格式或改传截图。
- 本机来源按网页版账号、录屏标识、分析类型隔离。切换账号/类型、取消或离开页面会停止未完成提取并释放视频资源。
- 确认后的截图沿用现有千问分析、积分和报告存储流程。来源图片只保存在采集时的浏览器，清除本地数据会失去来源回看；报告仍按原有规则保存。

## 验证

- `node scripts/test-video-import.mjs`：纯函数边界；加 `--browser` 验证真实视频录制和解码。
- `node scripts/test-desktop-capture.mjs`：来源合并、账号隔离与真实 IndexedDB。
- 浏览器交互验收包含真实合成 MP4 的静止、短回复变化、滑动画面，以及裁剪、删除、调序、取消、切换账号、导入分析页和确认前无材料上传。
- 手机尺寸测试不等于 iPhone/Android 真机解码验收；新的系统或视频编码仍需在对应设备验证。
